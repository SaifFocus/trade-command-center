# Scoped project rules

- Trading Agents page (`/agents`): the agent registry is `public.desk_agents` (migration 0022) and runs go to `desk_agent_runs` only through service_role-only `desk_log_agent_run(key, status, summary, items, started_at)`. The page reads everything about each agent with owner-gated `desk_agent_status()` (registry, live pg_cron schedule, last run, 24-hour counts) plus the run tables under owner-only RLS. Why: one source of truth for what runs, and nobody but the owner can read it.
- Every cron route wraps its job in `recordRun(db, "<agent key>", () => job(db))` (`runs.server.ts`). A failed log never fails the job; a thrown job is logged as an error and rethrown. Summaries come from pure `summarizeRun` in `agents.ts` (tests in `agents.test.ts`); add a case there when a job's result changes shape. A new background job needs a `desk_agents` row and a `recordRun` key, or the page will not show it. Why: the page shows what each run actually did, not only that pg_cron started it.
- Claude scheduled tasks (signal reviewer, daily brief, weekly review, Invo re-scout) log their own runs by calling `desk_log_agent_run` as their last step; their schedules are stored in `desk_agents.schedule` and must be updated there if the task's schedule changes. The Invo bridge is read from `invo_bridge_runs` (offline after `BRIDGE_OFFLINE_MIN` silent minutes). Why: Claude tasks and the owner's PC are outside APEX, so APEX only knows what they report.
- Health is computed in the browser with pure `agentHealth` and the cron helpers in `cron.ts` (CRON_TZ supported, Swedish summer time handled): an agent is overdue when its latest scheduled run, minus a grace of 10 min (app) or 45 min (Claude), has no logged run. The page is view-only: switching jobs on or off stays with the desk settings and the kill switch. Why: a missed run shows up within minutes without any extra background job.
